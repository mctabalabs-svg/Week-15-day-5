Squashing is appropriate for cleaning up feature branches that contain messy work-in-progress commits, typos, and small iterative fixes before merging into the main branch. It helps present a clean, logical history that tells the story of the feature rather than the process of building it. Squashing is harmful when applied to public history on main or shared branches because rewriting commits that other developers have already pulled will cause merge conflicts and broken histories for everyone on the team. The --force-with-lease flag is safer than plain --force because it checks whether the remote branch has been updated by someone else since you last fetched, refusing to overwrite their work and preventing accidental data loss. The golden rule of rewriting history is never to rewrite shared history; only rewrite commits that have not been pushed or that exist solely on your local feature branch. When in doubt, preserve the existing commit history and create new commits instead of modifying old ones.
